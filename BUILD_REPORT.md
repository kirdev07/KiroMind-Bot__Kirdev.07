## Обновление: Telegram-модуль
- **Токен**: `KeystoreSecretStore` — AES-256-GCM, ключ в Android Keystore, имя записи привязано к шифротексту. При ошибке расшифровки токен считается нечитаемым, незашифрованной копии нет. Токен сохраняется только после того, как Telegram подтвердил его через `getMe`.
- **Клиент**: `HttpTelegramBotApi` — только HTTPS, long polling (`getUpdates`, 25 с), `sendMessage` и `send*` по file_id или https. В исключения не попадает URL с токеном.
- **Цикл** `TelegramBotRunner`: старые сообщения при запуске пропускаются; 401/404 и 409 останавливают бота с понятной ошибкой; на 429 бот ждёт retry_after; при сбоях сети повтор через 2–60 с; между сообщениями в один чат не меньше 1 с; один отклонённый ответ (например, пользователь заблокировал бота) работу не останавливает.
- **Ответы** (`planReply`): подпись к первому вложению, если текст до 1024 символов; длинный текст делится по 4096; ссылки добавляются в текст; демо-вложения и локальные файлы пропускаются с записью в журнал; ответы внешнего ИИ помечаются.
- `/teach вопрос = ответ` работает только для ID владельцев (сохраняются между запусками) и записывает ответ в Room.
- **Сервис** `BotService` (foreground, `specialUse`) запускается только кнопкой на главном экране и показывает уведомление. После сбоя сам не перезапускается.
- **Разрешения**: INTERNET, FOREGROUND_SERVICE(_SPECIAL_USE), POST_NOTIFICATIONS. Незашифрованный HTTP по-прежнему запрещён.
- **Тесты**: 76 на компьютере (JSON, преобразование сообщений, план ответа, цикл бота с поддельным API в виртуальном времени, контроллер токена) и 7 на телефоне (Keystore и Room). Все проходят.

## Обновление: автообновление через GitHub Releases
- `UpdateManager`: проверка `releases/latest` в `kirdev07/KiroMind-Bot__Kirdev.07` раз в сутки при запуске и по кнопке «Настройки → Приложение → Обновления». Скачивание только по HTTPS с хостов GitHub, до 300 МБ, с отменой. Перед установкой проверяются SHA-256 (файл `.sha256` или строка в описании релиза; без суммы установка запрещена), имя пакета, что `versionCode` новее установленного и совпадает с тегом, а также ключ подписи (SHA-256 сертификатов). Установка идёт через `PackageInstaller`, и Android всегда спрашивает подтверждение. Разрешение `REQUEST_INSTALL_PACKAGES` выдаёт пользователь, на экране есть кнопка «Открыть разрешение».
- Версия: `versionName` из тега (`-PappVersion`), `versionCode = major·10000 + minor·100 + patch` (сейчас 1.0.0 → 10000). Подпись релиза берётся только из переменных окружения или секретов CI.
- `.github/workflows/release.yml`: по тегу `v*.*.*` прогоняет тесты, собирает подписанный APK, считает SHA-256 и создаёт релиз. Инструкция — в `RELEASING.md`. **В GitHub ничего не отправлено**: нужна явная команда владельца, ключ подписи и секреты репозитория.
- Тесты: 120 на компьютере (сравнение версий, формула versionCode, разбор релиза, отказ для черновика, тега без версии, двух APK, http и чужого хоста). Все проходят. На телефоне автопроверка при запуске показала «в репозитории пока нет релизов» — это соответствует действительности.
- Не проверено: загрузка и установка обновления — в репозитории ещё нет релиза. Важно: сейчас на телефоне стоит отладочная сборка, поэтому первый релиз поверх неё не встанет (другой ключ подписи); это описано в `RELEASING.md`.
