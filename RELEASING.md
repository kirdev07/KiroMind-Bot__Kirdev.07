# Выпуск обновлений KiroMind Bot

Приложение само проверяет последний релиз в репозитории
[kirdev07/KiroMind-Bot__Kirdev.07](https://github.com/kirdev07/KiroMind-Bot__Kirdev.07)
раз в сутки и по кнопке «Настройки → Приложение → Обновления».

## Что приложение требует от релиза

- Тег вида `v1.0.1`: из него берутся `versionName` (1.0.1) и `versionCode` (10001).
- Ровно один файл `.apk` и рядом `<имя>.apk.sha256` (или строка `SHA-256: <hex>` в описании релиза).
- APK подписан **тем же ключом**, что и установленная версия. Иначе установка отклоняется.
- Черновики и pre-release игнорируются.

Перед установкой приложение проверяет SHA-256, имя пакета, что версия новее установленной
и совпадает с тегом, а также ключ подписи. Установку всегда подтверждает пользователь
в системном окне Android.

## Один раз: ключ подписи

```bash
keytool -genkeypair -v -keystore kiromind-release.jks -alias kiromind -keyalg RSA -keysize 4096 -validity 10000
```

Храните `kiromind-release.jks` и пароли **вне репозитория**. Потеря ключа означает,
что обновления «поверх» станут невозможны.

Секреты репозитория (Settings → Secrets and variables → Actions):

| Секрет | Значение |
|---|---|
| `KIROMIND_KEYSTORE_BASE64` | `base64 -w0 kiromind-release.jks` |
| `KIROMIND_KEYSTORE_PASSWORD` | пароль хранилища |
| `KIROMIND_KEY_ALIAS` | `kiromind` |
| `KIROMIND_KEY_PASSWORD` | пароль ключа |

## Выпуск версии

```bash
git tag v1.0.1
git push origin v1.0.1
```

Сценарий `.github/workflows/release.yml` прогонит юнит-тесты, соберёт подписанный APK,
посчитает SHA-256 и создаст релиз.

## Важно про отладочные сборки

APK, установленные через Android Studio или `adb`, подписаны **отладочным** ключом.
Релиз с GitHub подписан другим ключом, поэтому поверх отладочной сборки он не встанет:
приложение покажет «APK подписан другим ключом». Один раз удалите отладочную сборку
(данные пропадут: токен, база, настройки), установите релиз вручную — дальше обновления
пойдут сами.
